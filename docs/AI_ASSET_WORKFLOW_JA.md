# Tripo・Blender・Unityを使う品質改善の方針

2026-10-18。所有者提供のSac氏の記事を制作工程の参考にした。記事の再生数、紹介コードの特典、AIモデル名を制作結果や利用可能性の保証には用いない。Tripoは未登録との回答を受けている。外部への参照画像アップロード、契約、課金、追加ソフト導入はしていない。

## 今必要なソフト

追加購入は不要。導入済みのUnity 6000.6.5f1 / HDRP 17.6.0、Blender 5.2.0 LTSで今回の部屋・素材・動作の試作を進める。実機のUnity CLI 1.0.0-beta.12とPipeline 0.8.0-exp.1も確認できた。既存の設定を使用し、更新・再インストールはしない。

| 道具 | このゲームでの役割 | 導入判断 |
|---|---|---|
| Unity HDRP・Blender | 実ゲーム、編集可能なモデル、布の形状、リグ、描画 | 導入済み。継続使用 |
| Tripo Studio | 有機的な小物の初期メッシュを画像から生成 | 任意。最初は小物1点で比較。契約前に現行のプラン・利用条件を確認 |
| Auto-Rig Pro | IK操作、スキニング、リターゲット作業の効率化 | 有料・任意。既存11ボーンGenericリグがあるため、購入を前提にしない |
| Mixamo | 二足人型アニメーションの素材 | 任意。Adobe IDが必要。短い脚・大きな胴体のくまにそのまま適用せず、接地と歩幅を調整 |
| EC2 / GPUクラウド | 大きな処理を移す場合の選択肢 | 今回は不要。主対象のM3 Max / Metal上で確認する |

[Unity公式CLI](https://docs.unity.com/en-us/unity-cli/use-unity-cli)と[Pipeline](https://docs.unity.com/en-us/unity-cli/unity-pipeline/unity-pipeline-package)はEditorのローカル操作経路。CLI導入そのものは画質を改善しない。[Auto-Rig Pro公式ドキュメント](https://lucky3d.fr/auto-rig-pro/doc/index.html)にはBlender対応とリギング／リターゲット手順がある。[Mixamo公式FAQ](https://helpx.adobe.com/jp/creative-cloud/faq/mixamo-faq.html)では二足人型の制約を確認する。

## アセットを分けて仕上げる

「完成イメージ → 必要なアセットの分解 → 個別制作 → Unityの固定カメラと動きで比較」という工程を採用する。一括生成した部屋や高密度メッシュだけを完成とはしない。

| 対象 | 制作方法 | 最初の合格条件 |
|---|---|---|
| くま | 現行BlenderソースとGenericリグを継続調整 | 正面マスターの顔・比率を維持。横・背面・足裏と動く接地を確認 |
| 毛 | 現在のスキン付き短毛メッシュを実機比較 | 逆光の輪郭、面の密度、時間方向のちらつき、負荷を分けて判断 |
| 布団 | Blenderで重力・マットレス衝突を計算した形状を使用 | 厚さ、縁、縫い目、接触。現在は静的形状で、ゲーム中の布変形ではない |
| 編み物・編みかご | Blenderで交差・糸・縁をモデル化 | 近景で板や金属に見えない。穴や陰影が読み取れる |
| 壁・床・棚 | 寸法と面取りを管理したBlender形状＋HDRP素材 | 木目の方向、粗さ、接触影が実寸に合う |
| 布製収納箱・脇役のぬいぐるみ | Tripoを試す候補。まだ未生成 | 個体1点の比較で改善を示してから増やす |
| 窓外 | 立体の木々と実際の空 | 回り込んでも成立する奥行き。参考画像を背景として貼らない |

くまのマスターは `reference/bear_master_20261012.jpg`、補助は `reference/bear_turnaround_20261012.png`。部屋の構図と光は `reference/twilight_star_room.png` / `reference/twilight_bear_walk.png`。正面の顔を新しいAI生成結果で置き換えない。

## Tripoを最初に試すとき

1. 最初は布製収納箱1点。背景や照明を含まない、対象だけの整合した画像を準備する。4面を使う場合、正面・左右・背面で形と模様を一致させる。現在の全方向シートは上面・足裏も含むため、そのまま4入力画像として流用しない。
2. [Tripo公式のゲーム制作手順](https://www.tripo3d.ai/blog/workflow-game-scene)を参照し、ゲーム用メッシュと高密度形状の目的を分ける。[P2.0のキャラクター制作手順](https://www.tripo3d.ai/blog/mesh-game-character-p-2)は編集可能なメッシュを起点にする。高密度H3.1は形状参照やベイク元の候補であり、そのまま実ゲームへ入れる前提にしない。[H3.1公式説明](https://www.tripo3d.ai/blog/introducing-hd-model-v3-1/)
3. Blenderで実寸・軸・法線・穴・UVを点検。ライティングの焼き付いた色を除き、粗さと法線を分ける。形状の修正と必要なリトポロジーを行う。
4. 初回の小物は10,000〜30,000三角形を仮予算とする。これは今回の制作上の開始値で、Tripoの保証値ではない。カメラ距離と実測に応じて変更する。
5. Unityの保護された新しい生成リビジョンに取り込む。同一カメラ、露出、解像度で現在の小物と比較する。静止画・回転・衝突・メモリを確認してから採用する。

生成用の指示例：

> 子ども部屋に置く、角が柔らかい布製収納箱を1個。外寸は幅0.38m、高さ0.28m、奥行0.30m。淡い青灰色の綿麻、生成りの縁取り、前面中央に小さな白い雲の縫い付け。布の厚さと自然な軽いしわ、別形状として読める取っ手。文字、ブランド、家具、部屋、影の背景を含めない。ゲーム用に編集可能なメッシュとUVを作り、強い照明や陰影をベースカラーに焼き込まない。

これは依頼用の仕様で、実際の生成結果ではない。画像・モデルを外部サービスへ送る前に、使用する画像と送信先を所有者と確認する。

## インポート記録

入手元URL、作成日、生成モデルと設定、元ファイルのハッシュ、権利・公開条件の確認状況を残す。参照画像の保有と、外部サービスへの送信・一般公開の権利を混同しない。

Unityはm / Y-up / +Z-forward。Blenderレシピ内ではUnity座標から `(x,-z,y)` に変換し、FBXは `axis_forward=-Z, axis_up=Y, FBX_SCALE_UNITS`。実インポート後に寸法・前方マーカーを再確認する。

HDRP LitのMask MapはR=Metallic、G=AO、B=Detail Mask、A=Smoothness。Base ColorはsRGB、法線・Maskは線形としてインポートする。Roughness画像をSmoothnessとしてそのまま使わない。毛や布の柔らかさは、色・高密度形状・HDRPの導入だけでは成立しない。輪郭、法線、反射、接触と光を同時に調整する。

## この先の優先順位

まず新版の部屋の固定描画と短いPlay動画を比較する。次は窓とランプ周囲の間接光・柔らかい影の小規模なベイク試験が最優先。現在のHDRP AssetはSSGI無効であり、今回の補助ライトを物理的なGI計算と呼ばない。くまの脚・足運びは既存版を維持し、質量感、旋回、速度の変化を動く画面で評価する。モデルやアニメーションへの追加課金は、その比較で不足が具体化してから判断する。
