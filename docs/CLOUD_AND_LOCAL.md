# Codex Cloudと手元Macの開発フロー

**方針：クラウドはソースと制作手順を作る。MacはUEを動かし、ビルド・絵・性能を確かめる。**

## 1. クラウドで任せる範囲

OpenAIの現行資料では、Codex Cloudはリポジトリ・依存・アクセス設定を持つ環境を用意し、タスクごとの作業領域でコード編集・コマンド実行・結果レビューを進められる。[S1][S2]
本プロジェクトでは次の分担を採用する。特定のGPU、UE Editor、macOS SDKが標準で利用できると仮定しない。

| 作業 | Codex Cloud | Macローカル |
|---|---|---|
| 要件の整理、C++・設定の生成と修正 | 主担当 | 差分を確認 |
| 純粋C++ロジックのテスト、JSON検査 | ツールがあれば実行 | 同じチェックを再実行 |
| UE C++の正式ビルド | UEが別途実際に利用可能な場合だけ | UBT/UHTで必須 |
| UE Editor Python／Blender Python作成 | 主担当。構文と独立部分を検査 | 実際のUE／Blender内で実行 |
| モデル、Groom、マテリアル、マップの生成 | レシピとスクリプトを作る | Editorで生成・取り込み・保存 |
| Shaderコンパイル、Metalの挙動 | Mac合格の代替にしない | 必須 |
| 画質の比較 | 提供された実画像・動画を分析 | 画像と動画を採取し所有者が承認 |
| FPS、メモリ、LODの評価 | ログを整理。推測値で合格にしない | 実機で測定 |
| Macネイティブのパッケージ | スクリプトを準備 | 実行して起動確認 |

UEを使えるLinuxの専用CIを後日追加する余地はある。EpicにはUEのコンテナ向け資料があるが、それは「Codex標準環境で自動的にUEが使える」ことを意味しない。Engineへの正当なアクセス、依存、容量、実行権限等を別に確認する。[S11]
最初からEngine全体をクラウドへ入れる計画にはしない。

## 2. Gitリポジトリを準備する

新規の個人用・非公開リポジトリを初期案とする。これは公開を禁止するものではなく、参照画像や制作資産の権利・扱いを確認するまでの運用上の選択。
このパックを置く際は、**内側のAGENTS.mdがリポジトリのルートに来る**ようにする。二重フォルダーに埋めない。
既存のAGENTS.mdやコードがある場合は差分を読み、UE新版の方針と競合する旧Web専用指示を整理する。無断削除しない。

初期コミット対象は `AGENTS.md`、`REQUIREMENTS_JA.md`、`docs/`、`prompts/`、`reference/`、`templates/`、`scripts/`、`project.environment.json`。
`validation/handoff_checks.json`はこの文書パックの検査記録であり、ゲームのテスト結果ではない。

`reference/`の画像を一緒に入れる。Codexにはこの会話や添付の履歴が自動で届くと考えない。
既存のブラウザ版を置く場合は、別リポジトリか`legacy/`のアーカイブにする。旧AGENTS.mdを新版のルートへコピーしない。

## 3. Codex Cloudの環境を設定する

現行公式UIでは `Work in > Cloud` から環境を作り、GitHubリポジトリを選択、設定を確認してPublishする手順になっている。画面の提供状況・管理ポリシーによって異なる可能性がある。[S1][S2]
旧画面のSetup scriptと現行のInstall scriptを混同しない。操作名ではなく、以下の実行契約を満たすことを重視する。

### セットアップの指示文

> このリポジトリはUnreal Engineゲームのソースと制作指示を管理します。クラウド側は軽量なテキスト編集・構文検査・UE非依存テストだけを担当します。まずPython 3とGitが使えることを確認し、`bash scripts/cloud_setup.sh`を実行してください。UE本体、Xcode、巨大なアセット、Blender、GPUサービスを自動導入しないでください。UE依存のテストはNOT RUNとして残し、手元Macで実行する手順を管理します。

Install script／Setup scriptを直接入力する方式なら：

```bash
bash scripts/cloud_setup.sh
```

スクリプトはインストーラーではなく、軽量な前提確認と文書整合チェックである。不足ツールがあれば非ゼロ終了し、必要性を報告する。勝手な大容量取得はしない。

### ネットワークと認証

初期のチェックはネット不要。必要な場合だけ公式ドキュメントと使用するパッケージ取得先へのアクセスを許可する。ネットワーク設定は実際の環境と管理ポリシーを確認する。[S2]
APIキー、GitHubトークン、Epicの認証情報はREADME・スクリプト・ログに書かない。本プロジェクトの初期クラウドタスクに、Epicログイン情報や課金APIキーは不要。
Unrealのライセンス認証やソースアクセスが必要な作業を勝手に迂回しない。

## 4. 最初のクラウドタスク

`prompts/01_CLOUD_FIRST_TASK.md`を貼り付ける。
最初はM0の調査と、M1のテキスト中心の最小実装を依頼する。作業領域にEngineがない場合でも、検査用のスクリプト、純粋ロジックのテスト、C++の下書き、Macでの生成手順を作れる。
ただし、正式ビルドはまだ成功していないと明記させる。UEのヘッダーを模した偽物でコンパイルを通すような検証はしない。

クラウドが返す最初の成果物には、最低でも変更一覧、実行チェック、未検証、Macで必要な操作、仮資産と完成資産の区別を含める。
自動マージは初期運用にしない。

## 5. Macでの初回確認

所有者はEpic Games Launcher、UE、対応Xcode、Blenderの必要分を用意する。バージョンは実機を見て決める。
UE 5.8の調査時公式Mac要件ではXcode 26.1.1推奨、26.4非互換の記述がある。これはその版に対する記載であり、将来の版や現在インストール済みのUEへ一律適用しない。[S4]

まず以下を読み取り、`project.environment.json`を埋める。端末のシリアル番号、ユーザー名、個人フォルダーの内容をクラウドへ送らない。

```bash
sw_vers
uname -m
xcodebuild -version
xcode-select -p
```

GPUコア数とメモリは「このMacについて／システム情報」で確認。UEの版はLauncher・Editor、またはEngineのBuild.versionで確認する。
Codex CLIを使う場合は、同じリポジトリの作業ディレクトリで `prompts/02_MAC_FIRST_RUN.md`を渡す。ローカルCodexはファイル編集とコマンド実行に利用できるが、許可・UEの導入・実行権限は実環境に依存する。[S12]

必要ならEngineの場所を、そのマシンの環境変数として渡す：

```bash
# 実際のインストール先を確認して設定。サンプルをそのまま使わない。
export UE_ROOT="<実際のEngineインストールルート>"
```

`sudo`、Xcodeの選択先変更、Engineアップグレード、古いプロジェクトの変換は自動実行させない。変更が必要なら理由と影響を確認する。

## 6. 実装の往復

クラウドPR → Macで差分確認と取り込み → UEビルド → アセット生成 → 固定カメラの実画面取得 → `templates/LOCAL_REPORT.md`で報告 → クラウドで修正、の順に回す。
失敗時は、最初の根本エラー、その前後のログ、再現手順、実行環境を返す。数千行の二次エラーだけを渡さない。
成功時も、ビルド成功と見た目の達成を分けて記録する。

Macで生成した`.uasset`や`.umap`は、決めたLFS／配布手順で保存する。クラウドがそれらを変更する必要がなければ、アセット台帳とサムネイルだけを読める状態にしてよい。
リポジトリのアセット参照先を壊す変更、マテリアルのパラメータ名変更、リグ変更には再取り込み手順が必要。

## 7. クラウドで実行できないときの扱い

UEがない：`NOT RUN: UE compile / editor scripts / render / package`。
`unreal`がない：Python構文だけの結果を示し、Editorでの実行は未検証。
`bpy`がない：Blender内での生成は未検証。
画像が読めない：目標画像を見たと主張せず、画像パスと未確認を報告する。
GPUがない：画質・性能を測ったと主張しない。
LFSがポインターのみ：実体未取得として扱い、仮メッシュへの置換は明示する。

クラウドからMacへのリモート操作や、自宅MacのCI常駐化は、この初期手順では行わない。必要になったらアクセス範囲・実行権限・停止方法を別に設計する。公開PRを無審査で自宅Macに実行させない。
