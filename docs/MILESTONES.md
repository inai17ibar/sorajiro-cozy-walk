## M0：環境と検証経路

**T00 / Cloud**：リポジトリと指示を読む。画像を開けたか確認。環境のOS、Python、Git、C++コンパイラ、UE／GPUの有無を列挙。大容量取得はしない。

**T01 / Cloud**：バージョンlock、機能対応表、アセットmanifest、軽量検査、ローカル実行手順の設計を用意。

**T02 / Mac**：UE、Xcode、macOSを確認して固定。小さなプロジェクトを起動して描画経路を記録。Groom Strands、Cards、Lumen、影のスモークチェックを計画する。

**完了ゲート**：未確認項目が明示され、採用UE版と最低限の起動方法が再現できる。互換性表は公式記述と実測を別欄に持つ。

## M1：短い操作可能な土台

**T10 / Cloud**：最小の`.uproject`とC++ Runtime module、Character、GameMode、カメラ、入力のソース、設定を作る。必要なEngine版が未確定なら候補と未ビルドを明記する。

**T11 / Cloud**：床・ライト・プレイヤー開始点のマップを実Editorで作る再実行可能な手順／スクリプトを用意。仮メッシュだけの段階と明記。

**T12 / Mac**：UBT/UHTでビルド、Editorでマップ生成、歩行とカメラ操作。エラーを先に修正。Macパッケージの最小起動経路を早めに試す。

**完了ゲート**：Macで起動し操作できる。これは完成モデルや最終画質の合格ではない。
**次はM2へ**：星・保存・UIを大量に作り込む前に、見た目の検証に移る。

## M2：主役と一場面の見た目

**T20 / Art + Cloud**：参照シルエットに近い全身メッシュ、UV、部位別材質、リグの制作手順。外部資産が必要なら先に権利・版を確認。

**T21 / Cloud → Mac**：L_LookDev、窓光、床、ラグ、本、固定カメラ4個、露出固定、実画面取得の再現手順。

**T22 / Mac → Cloud**：4枚の実画面を取得し、参照との差を文章で整理。顔・比率・材質・接地のうち重大なものから1〜2点ずつ修正。

**完了ゲート**：くまらしい形と布の基礎が実画面で確認できる。毛がまだ試作なら明示。主役が単色の球のままM2完了としない。

## M3：毛、動き、LODの採用試験

**T30 / Cloud + Mac**：小さなGroomパッチの出力・取り込み・Binding試験。工程と対応版を固定。Macで実際に表示。

**T31 / Cloud + Mac**：全身へ適用し、Cards／Mesh版と比較。固定カメラ・同一照明・同一姿勢で差を保存。

**T32 / Mac**：歩行、頭回転、近遠移動、LOD切り替え。30秒以上の連続実描画を確認。

**T33 / Cloud + Mac**：通常／高画質／軽量の3段階に整理。切り替えで何が変わるかを表にし、GPU時間と見た目の差を記録。

**完了ゲート**：方式の採用理由が画像・動画・性能に基づく。非対応や低画質の妥協は所有者の承認を取る。毛数だけで評価しない。

## M4：部屋全体と探索

**T40**：ベッド、本棚、植物、テント、電飾、籠、ブロック。通路を確保しつつ、近景から順に磨く。
**T41**：ジャンプ・衝突と簡単な到達テスト。足滑りや壁へのカメラ貫通を調整。
**T42**：星8個、安定ID、重複回収防止、全部集めた後のテントでの休憩。
**T43**：SaveGame、破損時の復旧、リセット確認、日本語UI、音量。
**T44**：フォトモード、UIなしの画像保存、元の操作へ復帰。

**完了ゲート**：一連のゲームを実際に最後までプレイでき、画質ゲートで得た見た目を保つ。セーブ／再起動の実ファイルでのテストも必要。

## M5：品質と配布可能性

**T50**：Macで固定ルート120秒×3回を測り、FPSではなくフレーム時間も報告。
**T51**：最も重いパスを確認し、主役の品質を崩さず最適化。変更前後の実画面を比較。
**T52**：MacパッケージをEditorなしで起動、30分の安定性、画像保存、セーブを確認。
**T53**：Windows／RTX 3070で同じシーンをビルド・描画。Mac専用の成功を流用しない。
**T54**：最終README、再現用環境lock、アセット元データ、権利一覧、既知の制限を整理。

**完了ゲート**：各対象機で、ビルド・資産・ランタイム・画質・性能が別々に合格。Windows未確認なら「Mac版のみ確認済み」とする。

## タスクの共通依頼形式

対象要件ID／変更するファイル／触らない範囲／実行環境／期待する確認／必要アセット／ブロック時の代替作業を1つのタスクに書く。
クラウドが返す報告は、実行結果と予定を混ぜない。次のマイルストーンを丸ごと未検証で「完成」にしない。
