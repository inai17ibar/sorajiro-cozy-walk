# 参照画像に近づけるためのレンダリング計画

## 1. 最初に作る画質検証シーン

`L_LookDev`を専用の小さな比較シーンとして作る。要素は完成を目指すくま1体、窓、木の床、ラグ、本数冊のみ。

M0・M1の後続入力を [lookdev_plan_v001.json](../Tools/Unreal/recipes/lookdev_plan_v001.json) と [次タスク](LOOKDEV_NEXT_TASK.md) に準備しました。くま・窓・床・ラグと4カメラを先に検証し、本はその後の追加です。これは計画レシピで、実マップ・完成くま・毛・実画面はまだ生成していません。
壁・光源・カメラを固定し、旧ブラウザ版の弱点を1つずつ置き換える。最終ゲーム用`L_SunlitRoom`とは分ける。
フォトリアルな部屋を一度に全部作ろうとして、主役の品質確認を遅らせない。

## 2. 参照画像の観察から決める美術

`bear_plush.png`では、頭が大きく、下半身は短く、青い短毛・白い口元・光沢のある黒い目と鼻が特徴。毛の長さよりも均一すぎない短い毛束と柔らかな輪郭が重要。
`target_room.png`では、小さな主役に対する巨大な家具、床近くの低いカメラ、右奥の窓光、木や布の暖かな色、青い主役との対比が中心。
背景のぼかしや眩しさだけをまねず、まず同じ方向の影・主役の画面占有率・床の接地感を合わせる。

素材の役割を分ける：青いフリース、白い短毛アップリケ、縫い糸、黒い樹脂、木、織物、籠。全部に同じroughnessや同じ毛を使わない。

## 3. キャラクター制作の順序

### A. シルエット

毛なしの中立材質でも参照のくまと分かる全身を作る。正面・横・背面で、頭胴比、耳位置、口元の出っ張り、腕脚の長さを確認。
軸とスケールを確定し、1回の書き出し・再取り込みで同じ大きさになることを確認する。

### B. 基布とアップリケ

UV、材質分割、色、roughness、細かな凹凸、雲の薄い厚みを作る。白い点は写真を投影しただけの照明焼き込みではなく、材質の色として扱う。
元画像には光と影が含まれるので、それをそのまま全方向のテクスチャとして使って「物理材質」と呼ばない。

### C. 毛と部位別設定

頭・耳・口元・胴・腕脚で毛流れを分ける。顔は目や鼻を覆わず、内耳を埋めず、口の線を保つ。
初期の短毛長は全高40cmのモデルに対して概ね1〜4mmの試験範囲から比較する。これは測定した実物値ではなく試作範囲。全身を同じ長さにしない。
まず小さなパッチを作り、逆光・正面光・影で確認してから全身へ広げる。

### D. リグへの追従

全身のSkeletal Meshに対応させ、頭を回す、腕を振る、脚を曲げる動作でGroomの根元が表面から離れないことを確認する。
頭部の剛体追従は比較候補になるが、胴体や関節をすべて剛体の毛で覆って継ぎ目を生まない。
初期は短い毛の物理を切り、良い造形と追従を優先する。必要な部分だけ後から揺れを追加する。

## 4. 毛の比較実験

最低2経路を同じメッシュ・模様・ライティング・カメラで比較し、`templates/feature_matrix.json`と実験レポートを更新する。

| 候補 | 期待する役割 | 必ず見ること |
|---|---|---|
| Groom Strands | 主役の近景と高品質設定 | SM6対応、Editor/パッケージ両方の表示、スキン追従、GPU時間、影 |
| Cards／Mesh | 通常距離・低負荷設定・非対応時 | 横からの板っぽさ、輪郭、透過重なり、モアレ、TSR残像 |
| 表面の布シェーダーのみ | 遠景LODと基布 | 毛なしの近景を最終品質として扱わない |

同時に変える変数は少数にする。毛の密度、長さ、点数、幅、影、LOD、補間、AAを分けてA/B比較する。
Groomは曲線数以外に補間・ボクセル化・可視判定・照明・合成などのコストがあるため、毛数だけで性能を見積もらない。[S6]

採用基準は「主役の輪郭と布の印象が良く、移動中も破綻せず、目標のフレーム予算に収まる」こと。
Strandsが使えない場合は原因を切り分け、軽量版で検証を続けてよい。ただし品質未達は未達として記録する。

## 5. 光を合わせる手順

1. 色調処理を弱め、露出を固定。くまの白と青を正しく分離する。
2. 窓からの主光源を1つ決め、影の方向と柔らかさを合わせる。
3. 木の床と家具の間接光、反対側の弱い補助光を調整する。
4. 足元、顎の下、腕と胴の接触部を確認する。
5. 電飾、控えめなBloom、空気感を追加する。

ソフトウェアLumenを基準にする。背景の距離場やモビリティを適切にし、動くくまの影と反射を別途確認する。
ハードウェアRTの実験を行う場合は同一シーンの別プロファイルにし、Macでの実験的対応と不具合を記録する。[S4][S7]
Groomのベイク照明には制約があるため、室内の光を完全ベイクへ変更する場合は毛の照明も実機で検証する。[S5]

## 6. 部屋のディテール配分

最優先はカメラに近い床板の目地と面取り、主役の周囲のラグ、毛布の裾、本と木のブロック。
ベッドや本棚は形と厚みから作り、木目画像だけで角の鋭い箱を本物に見せようとしない。
毛布は布の厚みと重さのあるしわを持ち、初期は静的に整えた形でよい。布シミュレーションは後回し。
植物の葉や籠も、主役以上の描画コストを使わない。ラグ全域を高密度Strandsにしない。
Naniteは背景の候補として評価し、アニメーションや毛やGIの問題まで自動解決する機能として扱わない。

## 7. カメラと画面仕上げ

ゲーム用カメラはくまの背後やや上から。小さな主役と巨大な室内が伝わる低い視点にする。
初期は水平画角50〜65度を比較し、最終値を記録。これは設計試験範囲で、参照画像の正確なレンズ推定ではない。
ゲーム中は操作に必要な手前と進行方向が見えるようにし、強いDOFは主にフォトモードで使う。
モーションブラーとDOFを切った画面でも良い見た目になること。DOFで毛に縁取りが生じる場合は設定と方式を比較する。[S5]

## 8. 固定して撮る画面

| Shot ID | 構図 | 検査するもの |
|---|---|---|
| S01_Portrait | 正面の顔・肩 | 目、鼻、口元、雲、毛の色と密度 |
| S02_Gameplay | 後ろからの低い視点 | 部屋の雰囲気、しっぽ、毛の逆光、主役の大きさ |
| S03_ThreeQuarter | 斜めの全身 | 頭胴比、耳、手足、輪郭、縫い目 |
| S04_Contact | 足裏とラグ・床 | 接地、影、毛の重なり、床の質感 |

すべて実際のUE描画から取得。基準となるカメラ位置、姿勢、露出、解像度、時刻、Engine版、プロファイルを保存する。
スクリーンショットとは別に、待機→歩行→停止→カメラ旋回→距離変更を30秒以上撮る。
サムネイルだけでなく原寸画像を残す。動画・スクリーンショットはUEの実バージョンに対応する方法で取得する。

## 9. チェックリスト

輪郭が毛で柔らかい／目と鼻がプラスチックに見える／布が光沢プラスチックになっていない／雲に厚みがある／青と白が見分けられる／足が接地している／毛が画面移動で明滅しない／LODが突然消えない／くまをぼかしで隠していない。
結果は項目ごとに合格・要修正・未検証で残す。点数や「Pixar品質達成」という主観的な断言は不要。

## 10. 納品する制作資産

Blender等の元モデル、UV、テクスチャ元、リグ、歩行、Groomの生成元、使用したエクスポーター情報、UEインポート設定、バインディング、マテリアル、LOD、シーン、固定カメラ、変更前後の実画面を揃える。
最初の生成が粗い場合はプレースホルダーと明記し、手作業で直す部位を一覧にする。コードだけで最終的な美術品質が自動完成したとは扱わない。
